## 网页与服务

实验室内访问 `http://192.168.110.211:8792/`。
网页是共用控制台，由一名操作者控制，其他人观看；近景和居中也会影响其他访客。
默认启动为预览，不自动开始标定、拟合或正式演员录制。
网页“人体模型”可在 SMPL-X 身体＋双手与 SOMA 身体＋手腕（纯LBS）之间切换。
先停止保存，再切换；两种模型独立标定。未标定模板会明确标注为静态预览。

操作者账户 `wangboran` 的用户服务名为 `vicon2smpl.service`：

```sh
systemctl --user status vicon2smpl.service
systemctl --user start vicon2smpl.service
```

停服务前，先在网页停止拟合并确认保存。随后执行：

```sh
systemctl --user stop vicon2smpl.service
```

热环境固定前缀为 `/run/user/1003/vicon2smpl-runtime`，含独立 Python、venv、代码、SDK 运行库、状态和缓存。
此目录不是持久数据目录，重启后由 `launch_cached.py` 按哈希从持久归档重建。
重建和服务运行各有单实例锁；已有不完整缓存会被保留并明确报错，不能直接覆盖。
用户服务模板及恢复机制见 [部署说明](DEPLOYMENT.md)。

## 依赖包与离线恢复

`requirements-linux-cpu-py311.lock` 是 Linux x86_64、CPython 3.11 的完整版本快照，包含开发检查依赖。
它保留原SMPL-X运行时；双模型运行时的完整版本以发布目录 `requirements.lock` 为准。
运行包使用 Torch `2.5.1+cpu`；原项目的逐帧求解在 CPU 上运行，模型与手部先验仍按原生 SMPL-X FK/LBS 使用。
这是独立部署环境，保留原共享 Conda 环境，不把其数百个无关包复制进来。

`current/portable-bundle.tar.gz` 是内部完整包，包含独立 Python、wheelhouse、SDK、授权模型、代码和哈希清单。
在有足够空间的独立目录解包后，执行包内 `restore.sh`，再按包内说明运行健康检查。
恢复过程不访问包索引；版本、文件 SHA256、Torch CPU 构建与模型/先验均需检查。
具体发布提交、包大小与检查结果以 `current/acceptance.json` 为准。

外网查看网页时，复用自己已有的 4090D 持久 SSH 连接添加本地转发，不开放公网控制端口。
正式录制继续使用原有 Zenbook / Shogun 流程；本服务只读动捕数据并保存独立派生结果。
